# Pennsieve metadata records, version 1.0

Identifier: `https://schemas.pennsieve.io/structures/pennsieve-records`
This version: `https://schemas.pennsieve.io/structures/pennsieve-records/v1.0`
Registry id (app.yml `conformsTo`): `pennsieve-records`, or
`pennsieve-records@1.0` for this version

A dataset's metadata records, one version of each model, as an app reads
them. An app asks for them with an input of this structure; a run fills it
from a dataset view, with the records the view pins. It is the layout of
Pennsieve's metadata export without the `versions/<n>/` level: a run pins one
version of each model, so there is only one.

## Layout

```
models/
  <model>/
    schema.json         the model's JSON Schema (required)
    records.jsonl       its records, one per line (required; may be empty)
relationships.csv       links between the records (required; may be only the header)
files.csv               which files each record is linked to, when the source has any
.pennsieve/view.json    the dataset view the records came from, when they came from one
```

- `<model>` is the model's name in its dataset (e.g. `subject`, `sample`).
  Models are dataset-specific: an app shouldn't assume which ones there are,
  or should say in its description which it expects.
- Paths are case-sensitive. There is nothing else in the folder.

## models/&lt;model&gt;/schema.json

The model version's JSON Schema: an `object` whose
`properties` are the record's fields, with their types and `required`. Pennsieve
annotations on a property include:

| Annotation | Meaning |
|---|---|
| `x-pennsieve-key` | the field is (part of) the record's key |
| `x-pennsieve-unit` | the field's unit, e.g. `"mg"` |
| `x-pennsieve-sensitive` | the field holds sensitive data |

Other `x-pennsieve-*` annotations (common data elements, value sets) may
appear; readers ignore what they don't know.

## models/&lt;model&gt;/records.jsonl

[JSON Lines](https://jsonlines.org/): one record per line, each an object

```json
{"id": "6c1e…", "data": {"subject_id": "sub-01", "age": 34, "sex": "F"}}
```

- `id`: the record's id, unique across the dataset; relationships use it.
- `data`: the record's fields, as the schema describes them. A field without
  a value may be missing.

## relationships.csv

CSV with a header row:

```
source_record_id,target_record_id,relationship_type
6c1e…,a92f…,has_sample
```

Only links between records in the folder are listed.

## files.csv

CSV with a header row, `record_id,package_id,path`: a record's link to a file
of the dataset, with the file's path in the dataset when known.

## Reading it

With [DuckDB](https://duckdb.org/), one table per model:

```python
import duckdb
from pathlib import Path

root = Path(INPUT_DIR) / "records"   # the input's folder
con = duckdb.connect()
for model in (root / "models").iterdir():
    con.sql(f"""CREATE VIEW "{model.name}" AS
        SELECT id AS record_id, data.* FROM read_json('{model}/records.jsonl',
            format='newline_delimited', sample_size=-1)""")
con.sql(f"""CREATE VIEW relationships AS
    SELECT * FROM read_csv('{root}/relationships.csv', all_varchar=true)""")
con.sql('SELECT * FROM "subject"').df()
```

An empty `records.jsonl` has no columns to infer: read it with
`columns={'id': 'VARCHAR', 'data': 'JSON'}` instead.
