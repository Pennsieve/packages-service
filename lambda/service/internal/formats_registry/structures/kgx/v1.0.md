# Knowledge graph (KGX tables), version 1.0

Identifier: `https://schemas.pennsieve.io/structures/kgx`
This version: `https://schemas.pennsieve.io/structures/kgx/v1.0`
Registry id (app.yml `conformsTo`): `kgx`, or `kgx@1.0` for this version

A dataset's metadata records as a knowledge graph, in the tables of the
[Knowledge Graph Exchange](https://github.com/biolink/kgx) (KGX) format: one
table of nodes, one of edges. It is the graph input of open-source graph
tools (NetworkX, GRAPE, PyKEEN, PyG, KGTK, kgx, Neo4j import). An app asks
for it with an input of this structure; a run fills it from a dataset view
with the graph Pennsieve's metadata export renders from the records the view
pins. It is the export's `metadata/kgx/` folder without that prefix.

[Biolink](https://biolink.github.io/biolink-model/) is used where it is known
and is not required: most categories and predicates are local to the
dataset (`pennsieve:`). `graph.json` says how much of the graph is Biolink.

## Layout

```
nodes.tsv.gz          the nodes: KGX TSV, gzipped (canonical)
edges.tsv.gz          the edges: KGX TSV, gzipped (canonical)
nodes.parquet         the same rows as nodes.tsv.gz, in the same order, typed
edges.parquet         the same rows as edges.tsv.gz, in the same order, typed
graph.json            what the graph is of and how it was made
graph_stats.yaml      the graph's summary, in kgx graph-summary's form
.pennsieve/view.json  the dataset view the graph came from, when it came from one
```

- A run brings exactly these files, all six always. A graph may have no
  edges: the edge files then have the header and no rows.
- A dataset without metadata records has no graph, and a run refuses a
  graph input from it.
- Paths are case-sensitive.

## Reading an input

The columns below are fixed for every dataset. Still, read them **by name**:

- The core KGX columns are what an app relies on: `id`, `category`, `name`,
  `provided_by` for nodes, and `id`, `subject`, `predicate`, `object` for
  edges.
- Ignore columns you don't know, wherever they are.
- Treat `properties` and the other Pennsieve columns (`knowledge_level`,
  `agent_type`, `primary_knowledge_source`, `original_predicate`,
  `pennsieve_property`) as optional: they may be missing or empty.
- Don't assume `pennsieve:` categories or predicates; Biolink ones may be
  there too.

That way the same app reads graphs from elsewhere in KGX form (Monarch KG,
KG-Hub graphs such as KG-OBO and KG-Microbe), which have other or more
columns and Biolink categories.

## `nodes.tsv.gz`, `nodes.parquet`

| Column | Value |
|---|---|
| `id` | A record: `pennsieve:<record uuid>`. A term: its CURIE (`MONDO:0005015`). |
| `category` | A record: `pennsieve:<model>`. A term: its ontology's Biolink class when the whole ontology is one kind (MONDO `biolink:Disease`, HP `biolink:PhenotypicFeature`, UBERON `biolink:AnatomicalEntity`, CL `biolink:Cell`, CHEBI `biolink:ChemicalEntity`, NCBITaxon `biolink:OrganismTaxon`), else the ontology prefix (`NCIT`, `MEDDRA`). A list. |
| `name` | A record: its key values (`x-pennsieve-key`); empty when it has none. A term: its label. |
| `provided_by` | A record: `pennsieve:<dataset uuid>`. A term: its ontology's id in the Biolink Information Resource Registry (`infores:mondo`), or empty when the ontology has none (MEDDRA, OBI, UO). A list. |
| `properties` | A JSON object. A record: its fields, as in `records.jsonl` of [pennsieve-records](../pennsieve-records/v1.0.md). A term: `ontology` and `ontology_version`. |

In Parquet, `category` and `provided_by` are `list<string>`; the others are
strings.

## `edges.tsv.gz`, `edges.parquet`

| Column | Value |
|---|---|
| `id` | `urn:uuid:<uuid>`, the same for the same edge in every build. |
| `subject`, `object` | Node ids. Every edge's ends are nodes of the graph. |
| `predicate` | A relationship between records: `pennsieve:<relationship type, lower case>` (`pennsieve:has_sample`). A coded value: `biolink:has_attribute`, from the record to the term. |
| `knowledge_level` | `knowledge_assertion` |
| `agent_type` | `manual_agent` |
| `primary_knowledge_source` | `infores:pennsieve` |
| `original_predicate` | Empty in 1.0. |
| `pennsieve_property` | A coded value's property (field) name; empty for a relationship. |

All columns are strings in Parquet.

- Relationships to records that aren't in the graph (a model the view didn't
  pick) are left out; `graph.json` counts them.
- Graphs of different datasets share term nodes: the same CURIE is the same
  node, so graphs can be joined on `id`.

## TSV rules

KGX TSV, as kgx reads and writes it:

- A header row; values separated by tabs; **no quoting** (read with
  `QUOTE_NONE`, `quoting=3` in pandas). A value can hold a `"`.
- List columns (`category`, `provided_by`) join their values with `|`.
- In text columns, a tab or line break is written as a space and `|` as `¦`.
  In `properties`, `|` is written `|`, so the JSON stays whole.
- An empty value is an empty string, not `NA`: read with
  `keep_default_na=False` in pandas.

For DuckDB, Polars, Spark and Neo4j, read the Parquet files: their CSV
readers don't all do `QUOTE_NONE`, and Parquet has the lists as lists.

## `graph.json`

- `layout` `kgx`, `layout_version` `1.0`, `conforms_to` this structure.
- `biolink`: `none`, `partial` or `full`, how much of the graph is Biolink;
  `biolink_version`, the release the Biolink parts are from.
- `canonical` `tsv`, `files` (nodes, edges, summary) and `derived` (the
  Parquet files).
- `source`: the dataset (and view) the graph is of; `generated_at`, when the
  records were read (a view's pin time).
- `prefixes`: each CURIE prefix's IRI (`pennsieve` is `urn:pennsieve:`).
- `models`: each model's category, the fields its node names come from, and
  per property its concept, value set, common data element and unit
  bindings, and whether it is sensitive.
- `counts`: nodes by category, edges by predicate, edges left out.
- `mapping`: how the graph was made from the records, in words.

Readers ignore keys they don't know.

## `graph_stats.yaml`

The graph's summary in the form `kgx graph-summary` writes (`node_stats`,
`edge_stats`, with `provided_by` and `primary_knowledge_source` facets). It
counts `pennsieve:` categories and predicates too, which kgx's own summary
leaves out.

## Sensitive fields

A property marked `x-pennsieve-sensitive` is in none of the files: not in
`properties`, not as a term, not in a name. `graph.json` lists it as
sensitive, without values.

## Loading it

`root` below is the input's folder, e.g. `Path(os.environ["INPUT_DIR"]) / "graph"`.

pandas:

```python
import json
import pandas as pd

nodes = pd.read_parquet(root / "nodes.parquet")
edges = pd.read_parquet(root / "edges.parquet")
# or the TSV, as kgx reads it
nodes = pd.read_csv(root / "nodes.tsv.gz", sep="\t", quoting=3, dtype=str, keep_default_na=False)
fields = nodes["properties"].map(json.loads)
```

DuckDB:

```python
import duckdb

con = duckdb.connect()
con.sql(f"CREATE VIEW nodes AS SELECT * FROM read_parquet('{root / 'nodes.parquet'}')")
con.sql(f"CREATE VIEW edges AS SELECT * FROM read_parquet('{root / 'edges.parquet'}')")
# records that share a term with another record
print(con.sql("""
    SELECT a.subject AS record, t.id AS term, t.name AS label, b.subject AS other
    FROM edges a
    JOIN nodes t ON t.id = a.object
    JOIN edges b ON b.object = a.object AND b.subject <> a.subject
    WHERE a.predicate = 'biolink:has_attribute' AND b.predicate = 'biolink:has_attribute'
"""))
```

NetworkX:

```python
import networkx as nx

g = nx.from_pandas_edgelist(edges, "subject", "object", edge_attr=["predicate"], create_using=nx.MultiDiGraph)
g.add_nodes_from((r.id, {"category": list(r.category), "name": r.name}) for r in nodes.itertuples())
```

GRAPE (Embiggen, ensmallen) reads plain TSV: gunzip the files first.

```python
import gzip, shutil
from ensmallen import Graph

for name in ("nodes", "edges"):
    with gzip.open(root / f"{name}.tsv.gz") as f, open(f"{name}.tsv", "wb") as out:
        shutil.copyfileobj(f, out)
g = Graph.from_csv(
    node_path="nodes.tsv", node_list_separator="\t", nodes_column="id",
    node_list_node_types_column="category", node_types_separator="|",
    edge_path="edges.tsv", edge_list_separator="\t",
    sources_column="subject", destinations_column="object",
    edge_list_edge_types_column="predicate", directed=True, name="graph")
```

kgx:

```python
from kgx.transformer import Transformer

t = Transformer()
t.transform(input_args={"filename": [str(root / "nodes.tsv.gz"), str(root / "edges.tsv.gz")],
                        "format": "tsv", "compression": "gz"})
graph = t.store.graph   # properties stays a JSON string
```

Neo4j: load the Parquet files, or the gunzipped TSV, with `neo4j-admin
database import` or `LOAD CSV` (field terminator tab), with `id` as the node
key and `category` as labels. kgx can also write the graph into a running
Neo4j (`kgx transform --output-format neo4j`).

## Other formats

Pennsieve writes only this layout. Other graph formats are conversions on
your side:

- RDF (N-Triples, Turtle): `kgx transform -i tsv -c gz --output-format nt`,
  with the `prefixes` of `graph.json` (`pennsieve:` is `urn:pennsieve:`).
- Neo4j: as above.
- TigerGraph: its loading jobs read the TSV (gunzipped) or Parquet, with
  `id`, `subject` and `object` as vertex and edge keys.
